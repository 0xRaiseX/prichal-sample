# prichal-sample

Приложение-образец для [Prichal](https://prichal.tech). Нажимаете «Deploy» —
через минуту в браузере открывается страница, которая говорит, что вы в проде,
и показывает живые данные о своём контейнере.

Нужно оно ровно для одного: увидеть весь путь целиком — репозиторий → сборка →
выкат → адрес в сети — на приложении, в котором нечему ломаться.

## Что внутри

```
server.js           HTTP-сервер на стандартной библиотеке Node, без зависимостей
public/index.html   страница, которую он отдаёт
package.json        одна команда запуска: node server.js
```

Зависимостей нет намеренно: `npm install` нечего скачивать, поэтому образ
собирается за секунды. Dockerfile тоже нет — Prichal определяет Node-проект сам
через Railpack, и это тот же путь, которым пойдёт обычный клиентский репозиторий.

## Маршруты

| Маршрут | Что отдаёт |
|---|---|
| `/` | страница «вы в проде» |
| `/api/info` | JSON: имя пода, аптайм, версия Node, счётчик запросов, коммит |
| `/health` | `{"status":"ok"}` — для проб доступности |

## Запуск локально

```bash
node server.js       # http://localhost:8080
PORT=3000 node server.js
```

Нужен Node 20+. Устанавливать нечего.

## Деплой в Prichal

1. Форкните или скопируйте этот репозиторий к себе.
2. В консоли Prichal: **New project** → выберите репозиторий.
3. Порт оставьте `8080` — сервер слушает именно его.
4. Deploy.

Переменные окружения не нужны. Если задать `GIT_COMMIT`, страница покажет его в
поле «Коммит»; без неё там прочерк — выдуманных значений страница не показывает.

Порт `8080` — не случайность: Prichal не подставляет `PORT` в контейнер, приложение
обязано слушать тот порт, который указан в настройках сервиса. Значение по
умолчанию там `8080`, и сервер берёт то же самое.

## Как убедиться, что это правда живое

Страница обновляет данные раз в 5 секунд. Перезапустите сервис в консоли — имя
инстанса сменится, аптайм обнулится. Значит, отвечает реальный контейнер в
кластере, а не кэш где-то по дороге.
